### 0.2 字典字段覆盖（`data/dict.js` 实测，2481 条）

| 字段 | 含义 | 覆盖 | 覆盖率 |
| --- | --- | --- | --- |
| `p` | 读音 | 2481 | 100% |
| `r` | 部首 | 2481 | 100% |
| `s` | 笔画数 | 2481 | 100% |
| `w` | 组词 | 2481 | 100%（字级） |
| `wm` | 组词释义 | 2481 | 100%（字级） |
| `en` | 英文单词 | 2477 | 99.8%（缺：呢/呀/吧/吗，均为语气助词） |

- 组词总数 **5838** 条，平均 **2.35** 个/字（最少 2、最多 3）。
- 落盘释义映射 **4982** 条 → **词级释义覆盖率仅 85.3%**，即 **950 个组词在界面上只有词、没有释义**。
  （README 称释义源 5038 条；实测落盘 4982 条，差 56 条，属源与落盘的正常损耗，但**「组词与释义覆盖 100%」的表述只在字级成立，词级是 85.3%**。）
- 标了多个读音（`p` 长度 > 1）的字 **99** 个，但只有 289 个字带 `pw` 上下文选音 → 多音字能力是「有机制、覆盖薄」。
- 笔画数分布：1–5 画 299 字 / 6–10 画 1349 字 / 11–15 画 737 字 / 16 画以上 96 字（最少 1 画，最多 23 画，均值 9.3）。

### 0.3 字帖覆盖（`data/strokes/*.js` 实测）

- 12 册字帖合计 **2481** 字，与生字集**一一对应**：生字缺字帖 **0**，字帖多余 **0**，每册缺失 **0**。
- 字典 `s`（笔画数）与字帖实际笔画轮廓数**不一致 0 字**（100% 一致）。
- → **字帖/字形这一层是当前最硬的资产，无短板。**

### 0.4 激励系统数值（`js/store.js` 实读）

| 项 | 数值 |
| --- | --- |
| 单字奖励 | `3 + 2×星级` → 0/1/2/3 星 = 3/5/7/9 金币（星至少给 1） |
| 整课通关 | `20 + 10×平均星级` → 30/40/50 金币 |
| 每日打卡领奖 | 30 金币 + 1 星 |
| 打卡门槛 | 每天写满 5 字，倒计时 5 分钟 |
| 宠物孵化 | 累计打卡 **7** 天 |
| 喂食成本 | **20** 金币/次，每 5 次升一阶，最高 2 阶 |
| **金币出口** | **全产品只有「喂食」一个** |

> **可直接算出的两个结论：**
> 1. **宠物系统天花板 ≈ 200 金币。** 满阶只需喂食 10 次 × 20 = 200 金币；按三星字 9 金币算约 **23 个字**（二年级 2–3 课），按一星字 5 金币算约 **40 个字**。**孩子写完第一课后半段，宠物就到顶了**，此后金币只进不出、无限堆积、无任何消耗点。
> 2. **打卡覆盖全字表需 496 天。** 2481 字 ÷ 5 字/天 ≈ 1.36 年，且这还不含任何复习。对 1–6 年级的使用周期来说，「打卡」这条路径根本走不完。

### 0.5 关键流程事实（静态阅读，供产品判断用）

- 首页主 CTA「开始写字」绑定 `data-go="learn"`，但全项目**不存在** `#scLearn` 这个 section，`TITLES` 里也没有 `learn` 这一项 → 点下去后所有 `.screen` 都会被摘掉 `.on`、而没有任何一个被加上，**内容区直接空白，只剩顶栏**。
  （这是静态阅读结论，**建议用 smoke-test 实跑复验**；但无论复验结果如何，「首页唯一主 CTA 指向一个未定义的页面」本身就是产品漏斗第一层的断裂。）
- `Store.levelUnlocked()` **恒返回 true**（代码注释写明「儿童模式：不锁死」）→ 闯关模式**没有任何解锁进度感**。
- `Store.pickDailyChars()` 恒定从 `1a` 开始按册顺序扫描 → **五年级孩子第一次打开，每日打卡推的也是「一、二、三」**。
- 全项目（`css/` + `js/` + `index.html`）**没有** `prefers-reduced-motion`、`prefers-color-scheme`、字号设置入口；`aria-*` 仅 3 处。CSS 字号出现频次最高的是 12 / 12.5 / 13 / 13.5 / 15px，另有 11px×6 处、10.5px×3 处。
- 宠物图鉴解锁状态只跟随「当前选中宠物」的 stage（`renderPet()` 中 `maxStage = cur && st.hatched ? st.stage : -1`）→ **换一只宠物后，已解锁的形态会重新显示为「未解锁」**，收集感被破坏。
- 一课写完后 `finishLesson()` 直接回字表页或首页，**没有「下一课」「复习」「错字回顾」任何引导**。

## 1. 一句话定位

> **一款「完全离线、零账号、零广告」的小学 1–6 年级汉字笔顺练习工具：用真楷体笔锋字帖 + 手写轨迹判分，让孩子照着统编版教材的 2481 个写字表生字，在平板上把笔顺练对。**

拆开看，它解决的是三件事：

1. **给谁**：小学 1–6 年级学生（实际主力是 1–2 年级，因为 3–6 年级的内容组织已退化成「第 N 组」），以及陪练的家长。
2. **解决什么**：家长辅导写字时最头疼的「笔顺对不对」——这件事肉眼很难判、家长自己也常常写错，而学校作业量大、无法逐字反馈。
3. **凭什么是它**：**离线 + 无账号 + 无广告 + 无追踪**，且字帖是带笔锋的真楷体轮廓（2481 字 100% 覆盖、与笔画数 100% 一致）。这在儿童教育产品普遍「广告 + 诱导订阅 + 采集数据」的环境里，是**稀缺且可信**的定位。

一句话概括当前状态：**内容资产（字形/课程/字典）已经很扎实，产品外壳（留存、闭环、家长端、传播）还停留在「功能能跑通」的阶段。**

## 4. 问题诊断（产品视角）

### 4.1 留存机制：有「钩子」，没有「回路」

- **有**：每日打卡（5 字/5 分钟）、连续天数、14 天日历、宠物孵化 7 天。
- **缺**：
  - 打卡是唯一有节奏的入口，但它**每天只推 5 个字、且恒定从一年级上册开始**，对中高年级孩子是「推了等于没推」。
  - 全字表 2481 字 ÷ 5 字/天 = **496 天**才能走完一遍，这条路径在真实使用周期里不可能完成。
  - 除打卡外，**没有任何「回来」的理由**：没有复习队列、没有错字提醒、没有「昨天那个字再练一次」。

### 4.2 激励系统：设计完整，但**天花板在第二个小时就被顶穿**

- 金币出口只有「喂食」一个；宠物满阶只需 **10 次 × 20 = 200 金币 ≈ 23 个三星字**。
- 结果是**典型的通胀崩坏**：孩子写到第二、三课时，宠物已到顶，金币开始无限堆积且无处可花 → 金币失去意义 → 宠物失去意义 → 打卡只剩「日历上一个勾」。
- 宠物图鉴还会在**换宠物时把已解锁形态显示为未解锁**，收集感被自己破坏。
- 孵化需 7 天打卡，意味着**前 7 天宠物系统零产出**，而这段恰好是新用户留存最脆弱的窗口。

### 4.3 家长参与度：**几乎为零**

- 家长是决策者与传播者，但产品给家长的只有「安全说明 + 导出 JSON + 一键清除」。
- 没有报告 → 家长无法判断「有没有用」→ 无法形成推荐话术 → 传播链断裂。
- 更糟的是：**家长须知页的醒目按钮之一是「清除全部学习记录」**，配合「清缓存即丢」的现实，等于把家长最怕的风险摆在最显眼的位置，却没有给任何解药。

### 4.4 学习闭环：**只完成了前两环**

完整闭环应为：**演示 → 练习 → 检验 → 复习 → 再检验**。
当前只有：**演示 → 练习**（然后弹个「写对啦」就结束）。

- 无检验环节：没有听写/默写/脱离字帖的考察（竞品「笔顺达人」有「听笔画默写」）。
- 无复习环节：`markChar` 只记录 `n`（次数）/ `s`（最好星级）/ `t`（时间戳），**不记录错在哪一笔**，因此无法生成错字本，也无法做间隔重复。
- 一课完成后直接回字表页，**没有「下一课」引导**，学习动线在最有成就感的时刻被切断。

### 4.5 内容深度与覆盖：**字形很强，语义层偏薄**

- **强**：2481 字字帖 100% 覆盖、与笔画数 100% 一致、楷体笔锋轮廓——这是护城河。
- **薄**：
  - 组词平均 **2.35 个/字**、上限 3 个，作为「组词拓展」偏少。
  - **词级释义只有 85.3%**（950 个词在界面上只有词、没有释义），README 的「覆盖 100%」只在字级成立。
  - 多音字 `pw` 覆盖 **11.6%**（289 字），99 个多读音字里大部分没有上下文选音。
  - 3–6 年级占 **68.9%** 字量，却只有「第 N 组」没有课文名——产品最大的差异化卖点（按课文）在七成内容上不成立。

### 4.6 适龄与无障碍：**为低龄做了「不惩罚」，但没做「读得清、看得清」**

- **做对的**：写错不扣分、不清空、不倒计时施压、自动演示正确笔画、按钮尺寸经 smoke-test 校验。
- **没做的**：
  - **字号**：正文普遍 10.5–13.5px，对一年级孩子偏小，且**没有字号调节**。
  - **无深色模式、无 `prefers-reduced-motion`**（笔顺动画是强动效，前庭敏感儿童可能不适）。
  - **无障碍属性仅 3 处** `aria-*`，读屏基本不可用。
  - **三档发音强依赖系统语音**：粤语/英语语音未安装时只能提示去下载，实际体验在大陆设备上大概率只有国语可用——「三档发音」这个卖点的真实可用性存疑。
  - **路径深度**：选册→单元→课→字 四级，对识字量本就有限的一年级孩子过深。

### 4.7 分享传播：**零**

- 「无外链、无追踪」是**正确且值得坚持**的儿童产品设计。
- 但「不联网」≠「不能分享」。缺的是**离线可生成的传播物**：孩子写对的整字 + 星级 + 日期，排成一张图或一页可打印字帖，由家长自主发到班级群/朋友圈。
- 当前产品的输出物只有一份机器可读的 JSON，**家长不会转发 JSON**。

### 4.8 最紧急的一个问题

> **首页唯一主 CTA「开始写字」点了会白屏。**（`data-go="learn"` 指向不存在的页面）
> 这是漏斗第一层直接断裂。无论后面的产品方案多好，孩子/家长第一次点最显眼的那个按钮就遇到空白页，第一印象即流失。

## 6. 不建议现在做的 5 件事

| # | 事项 | 为什么不现在做（含机会成本） |
| --- | --- | --- |
| 1 | **做 iOS / Android 原生 App 并上架** | PWA「添加到主屏幕」已能拿到全屏、离线、桌面图标的体验，上架带来的增量主要是「应用商店曝光」，代价却是：审核周期、儿童隐私合规、账号/支付体系、双端适配与发版成本。**机会成本**：同样的时间做 P0-2（册次设置）+ P0-5（家长报告），对留存的提升确定且可验证；上架是「可能带来更多用户」，前两者是「让现有用户不流失」。 |
| 2 | **接后端 / 账号 / 云同步** | 这直接摧毁产品最强的差异化——「无账号、不收集任何信息、完全离线」。一旦有账号，就要面对儿童个人信息保护的合规义务与家长信任质疑。**机会成本**：P0-3（本地备份/恢复文件）用极低成本解决了「数据丢失」这个真问题的 80%，却完全不动架构。**真要做云同步，也应该在 P0 全部完成、验证了留存曲线之后**。 |
| 3 | **加广告或内购** | 面向儿童，README 与「家长须知」明确承诺无广告无内购，这是信任的基石；加广告会直接背叛这个承诺，加内购则要连带做账号、支付、退款、儿童误购防护。**机会成本**：本产品的价值不在变现，而在于它可能带来的口碑与信任；在留存机制还没跑通之前讨论变现，顺序是反的。 |
| 4 | **把字库扩到 9000+ 字（Hanzi Writer 全量）** | 2481 字已 100% 覆盖小学写字表，再扩的字**不在任何教材里**，对「按课文练字」这个定位的价值接近零，却要重做一遍质量把关与体积管理（`data/strokes/` 已 6.2MB）。**机会成本**：同样的内容产能，投给 P1-4（补齐 950 个无释义的词 + 多音字）是**提升已有 2481 字的单位价值**，投给扩字是稀释。 |
| 5 | **做社交 / 作品广场 / 排行榜** | 儿童 UGC 社交意味着审核、举报、隐私、内容安全，成本极高且不可离线完成；而竞品「河小象」的作业广场之所以成立，是因为背后有真人老师点评体系在产出内容，本项目没有。**机会成本**：P1-6（导出一张可打印的字帖）用「离线生成 + 家长自主分享」拿到了 80% 的传播效果，成本是社交功能的十分之一，且不引入任何风险。 |

## 7. 30 天路线图建议

**前提假设**：单人/小团队投入，纯静态架构不变，不改现有文件之外的既有功能逻辑（只做增量与修正）。

### 第 1 周 · 止血与立骨架

| 天 | 事项 |
| --- | --- |
| D1 | 复验并修复首页主 CTA 白屏（P0-1 ①）；跑 `smoke-test.html` + `verify.js` + `regress.js` 建立基线 |
| D2–D3 | 册次/年级设置（P0-2）：首次启动选年级、记住当前册、改造 `pickDailyChars` 取字范围 |
| D4–D5 | 首页改造（P0-1 ②③）：「继续上次」直达 + 「今天写这 5 个字」入口 |
| D6–D7 | 存档备份/恢复（P0-3）：导出/导入存档文件 + 结构校验 + 版本兼容 |

**周末检查点**：新用户从打开到落笔 ≤2 次点击；换设备能恢复进度；打卡推的字与实际年级一致。

### 第 2 周 · 补学习闭环

| 天 | 事项 |
| --- | --- |
| D8–D9 | 错笔记录（P0-4 ①）：`markChar` 扩展 + 存档向后兼容迁移 |
| D10–D12 | 错字本页（P0-4 ②） + 打卡改为「3 新 + 2 复习」（P0-4 ③） |
| D13–D14 | 一课完成后的引导（「下一课」「去复习」）与整课连写衔接 |

**周末检查点**：故意写错几个字，验证错字本能抓到、第二天打卡能推出来。

### 第 3 周 · 家长端

| 天 | 事项 |
| --- | --- |
| D15–D17 | 本周学习报告（P0-5）：字数 / 平均星级 / 高频错笔 Top5 / 累计天数 / 当前进度 |
