# 派单 · 第 2 层前置修复：国语档读成粤语 + 语音诊断面板

> 你是寇豆码（Kou）· 工程师。本派单设计决策已由主理人拍板，**不要自行改变产品行为**。

## 一、现象（用户实测确认）

- **默认国语档**朗读，听起来**像粤语**。
- 不是声调问题，是**语种选错了**。

## 二、根因分析（主理人已确认的代码路径）

1. `pickVoice('zh')`（`app.js:53`）在「系统里没有可用的普通话语音」或「`getVoices()` 尚未返回内容」时**返回 null**。
2. `speakOne`（`app.js:126-138`）里 `if (TTS.by[kind]) u.voice = ...` —— 为 null 时**静默跳过**，只保留 `u.lang='zh-CN'`。
3. Chrome 找不到 `zh-CN` 语音时，会退用列表里第一个中文语音 —— macOS 上通常是 **粤语 Sinji**。
4. 唯一提示「系统没装该语音」的 toast 在 `applyVoice`（`app.js:736` 附近）里，**只有手动切换档位才触发**；
   默认就是国语档的用户永远看不到。

**结论**：`国语档 = 粤语` 是必然结果，不是偶发。必须让「找不到普通话语音」这件事**立刻可见**，
而不是静默用一个错的语音顶替。

## 三、要做的三件事

### 甲. 语音诊断面板（用户能自己查）
入口：**练字页语音三档旁边的「诊断」小按钮**，点击弹窗（复用既有 `modal()`）。

面板内容（都是真实数据，不要写死文案）：
- `speechSynthesis.getVoices()` 的**总条数**
- **所有中文类语音清单**：每行 `name — lang`，右侧标注它被哪一档使用（国语 / 粤语 / 未使用）
- 三档各自当前的状态：`已选 <语音名>` 或 `未找到 → 正退化为系统默认（可能读成粤语）`
- 「最后一次朗读实际用的」：`文本 / lang / 语音名`（为此需要在 `speakOne` 里记录一次）
- 每档一个**试听按钮**（读一个常见字，如「春」）
- 一行提示：如果国语档显示"未找到"，给出 macOS 的下载路径：
  「系统设置 → 辅助功能 → 朗读内容 → 系统声音 → 简体中文」，iOS/iPadOS 同路径

### 乙. 修 `pickVoice`（漏选）
- `zh` 的 `langOK` 扩展到：`zh` / `zh-CN` / `zh-SG` / `zh-Hans` / `cmn` / `cmn-Hans`（注意大小写与连字符/下划线都要覆盖，
  `langOf()` 已把 `_` 换成 `-`）
- **保持 `langBad` 继续排除** `zh-HK` / `yue` / `zh-TW` / `zh-Hant` —— **宁可判为"没装"，也绝不能让粤语冒充国语**
- 返回值语义要能区分三态：命中 / 列表尚未就绪 / 确实没有该语音

### 丙. 朗读前置守卫
- `speakOne` 在使用前，若 `TTS.by[kind]` 为空，先**重新取一次语音列表**再试（懒加载兜底，覆盖 `getVoices()` 延迟返回）。
- 若重新取后**仍然为空**：
  - **不要朗读**（不要用错的语音顶替）
  - 若该档位尚未提示过，弹一次 toast：「系统里没有{{档位名}}语音，请到 系统设置 → 辅助功能 → 朗读内容 里下载后再用」
  - 每次会话最多提示一次（沿用 `TTS.warned`）
- 这条规则对 `zh` / `yue` / `en` 三档一致生效。

## 四、验收标准

1. **默认国语档、且系统无普通话语音时**：不发出错误读音，明确提示，且诊断面板显示「未找到」。
2. **系统有普通话语音时**：国语档选中的语音 `lang` 为 `zh-CN`/`zh-Hans`/`cmn*` 之一，**绝不会是 `zh-HK`/`yue`/`zh-TW`**。
3. **粤语档仍选粤语、英语档仍选英语**，三档互不串用（不得因本次修改而回退）。
4. 诊断面板能列出真实的语音清单（条数与名称来自 `getVoices()`，不得硬编码）。
5. `speakOne` 的调用方式与既有接口**保持兼容**（`speakText` / `speakSeq` / `speakChar` / `autoSpeak` 签名不变）。
6. **三套校验全绿**：`verify.js`（57 项）、`regress.js`（38 项）、`run-smoke.js`（113 项）。
